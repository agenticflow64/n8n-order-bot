# Сценарий демо (≤ 2 минут)

Подготовка (заранее, до записи): `docker compose up -d --build` + `./workflows/import-workflow.sh`.

**Хронометраж: ~110 секунд.**

Примечание: модель по умолчанию `liquid/lfm-2.5-2.6b:free` — медиана ~4.5 с, заказ обрабатывается быстрее 5-секундного интервала опроса. Телефон в сводке нормализуется регэкспом из исходного текста (LLM иногда искажает цифры). Дубли ответов отсечены: повторная обработка того же текста не отправляет клиенту второе сообщение.

| Время | Экран | Действия / что говорить |
|-------|-------|-------------------------|
| 0:00–0:15 | n8n UI, вкладка workflow | Открыть workflow «Order Bot — приём заказов». Показать схему слева направо: два канала приёма (TG-опрос getUpdates + эмулятор) → «Сообщение или кнопка?» → нормализация → «Приветствие или заказ?» → LLM → разбор → Switch с тремя ветками (успех / ретрай / оператор) → backend → ответ клиенту. |
| 0:15–0:35 | n8n UI, Executions | Открыть пару прошлых выполнений: зелёные ноды, внутри «LLM: Извлечь заказ» — реально пришедший JSON со `service_type`, `urgency`, `contact`. Показать одно выполнение с веткой ретрая/эскалации. |
| 0:35–1:00 | Telegram, бот @auto_llm_1_bot | «Пишу боту как живой клиент». Отправить `/start` → мгновенное приветствие с примерами заказов (LLM не тратится). Отправить заказ текстом с опечатками («надо стрижку собаке на выходные…»). Через ~30 с (интервал опроса) приходит сводка с inline-кнопками «✓ Подтвердить» / «✗ Отменить». Нажать «✓ Подтвердить» → кнопки исчезают, текст сообщения меняется на «Заказ №N подтверждён, ждите звонка». |
| 1:00–1:20 | Эмулятор чата `localhost:8000/chat` | «Эмулятор — второй канал: шлёт вебхук в тот же workflow». Отправить сэмпл с чипса («стрижку собаке… срочно!!») — та же сводка. Нажать «Подтвердить заказ». Отправить мусорный текст («а вы вообще чё за контора??») → клиенту — человеческое «оператор подключится». |
| 1:20–1:40 | Админка `localhost:8000` | Оба заказа в таблице: подтверждённый (нажатие кнопки в TG уже поставило статус «подтверждён») и «Ручная обработка». Показать фильтры, счётчики, перевод в «в работе». |
| 1:40–1:50 | Терминал | Показать healthchecks: `docker compose ps` (healthy). Проговорить: тесты — `23 passed`, точность извлечения на 12 сэмплах и время ответа LLM — в README кейса. |

## Кадры для скриншотов

1. Вся схема workflow с под горящими (выполненными) нодами.
2. Input/Output ноды «LLM: Извлечь заказ» (сырой текст → чистый JSON).
3. Telegram: приветствие на /start + сводка заказа с inline-кнопками и правка после нажатия.
4. Чат эмулятора: сообщение клиента + сводка + кнопка подтверждения.
5. Админка: таблица заказов, фильтр по статусу, счётчики.
